# Contributing to Battleship

Thank you for your interest in contributing! We welcome contributions of all kinds.

## Code quality

- Write clean, readable, maintainable code.
- Follow SOLID principles and established design patterns.
- Use meaningful variable and method names.
- Keep functions small and focused on a single responsibility.
- Avoid code duplication (DRY).
- Comment your code where necessary, but prefer self-documenting code.
- Handle errors gracefully.

## Testing

- Write tests for your changes.
- Make sure all tests pass before you open a pull request.
- Aim for high test coverage.

## Branches and pull requests

- Name every branch `ticket/BSH-<number>-<short-name>`, for example `ticket/BSH-42-hit-sound`. The release script reads the ticket number from the branch name.
- Keep pull requests small and focused.
- Fill in the pull request template.
- Be respectful and constructive in code reviews.

## Questions

If you have questions, ask the team. We are happy to help!
